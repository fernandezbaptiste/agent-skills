3–5 at onceTeam's #1 productivity unlock — one worktree per task, each with its own Claude session

Team's top tip: Spin up 3–5 git worktrees at once — "the single biggest productivity unlock"
03 Model Choice 🧠
Opus 4.6Uses the most capable model for everything — no exceptions
+ Extended ThinkingAlways enables thinking mode alongside Opus
Not SonnetDespite being slower per-token, Opus requires less steering and makes fewer tool-use mistakes
Net resultSlower model → faster total wall-clock time because you fix fewer mistakes
Token costNever optimises for token cost — gives engineers unlimited tokens
Principle: "A less intelligent model burns more tokens correcting mistakes than a smarter one spends getting it right"
Planning & execution workflow
04 Plan Mode 📋
Shift+Tab ×2Enters Plan mode — how most sessions start for any non-trivial task
Iterate on planGoes back and forth with Claude until the plan is solid before writing any code
Auto-accept modeSwitches to auto-accept edits once plan is locked — Claude can usually 1-shot the entire PR
Dual-Claude reviewOne Claude drafts the plan → a second Claude reviews it as "staff engineer"
Re-plan on failureIf execution goes sideways, switches back to plan mode and re-plans rather than patching
Key insight: "A good plan is really important — the execution follows naturally from it"
05 CLAUDE.md 📁
/ (repo root)Single shared CLAUDE.md checked into git — the team's institutional memory (~2,500 tokens)
Every mistake →Adds every Claude error to CLAUDE.md so it never repeats across any future session
After correctionExplicitly asks Claude to update CLAUDE.md itself to lock in the lesson
PR reviewsTags @.claude on coworkers' PRs → Claude updates CLAUDE.md as part of the PR diff

Iterate ruthlessly: "Prune CLAUDE.md over time until you see the mistake rate drop"

Boris's 3 principles & philosophy
16 Boris's 3 Principles (Shared with Every New Team Member) 🏆
1.
"What's better than doing something? Having Claude do it."
Default to delegating to Claude first. If a task can be done by Claude, it should be. This shifts the human role to directing, reviewing, and steering — not typing.
2.
"Underfund things a little bit."
Keeps teams deliberately lean so engineers are forced to Claude-ify their work rather than solving problems with headcount. Constraint drives creative AI adoption. "People are kind of forced to Claude-ify." Never cost-cut tokens — cost-cut people instead.
3.
"Encourage people to go faster."
Speed was Claude Code's original competitive advantage ("just me vs. a crowded market") and remains the core team value. To go faster: have Claude do more. Anthropic has seen 200% engineer productivity increase since adopting Claude Code internally.
Boris's philosophy: Claude is moving beyond writing code → it now looks through bug reports, telemetry, and feedback to suggest features to ship
